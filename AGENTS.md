# AGENTS.md — Ant Design Pro

This file is written for AI coding agents. It assumes no prior knowledge of the project. Read it before modifying code, running tests, or generating new files.

## Project Overview

Ant Design Pro is an out-of-the-box React enterprise application boilerplate. This repository is version `6.0.2` of the official template.

- **Frontend**: React 19 + TypeScript 7 + Umi Max 4 + antd 6 + ProComponents 3.
- **Bundler**: Umi Max ships with `max build` locally; CI uses the `utoo` toolchain (`ut build`, `ut lint`) which wraps `utoopack` (Rust-based bundler used by Umi Max v4).
- **Styling**: Tailwind CSS v4 → antd-style v4 / `createStyles` (theme tokens) → CSS Modules → Less (legacy only).
- **State**: Umi Max data flow (`initialState`, `src/models/`) plus `@tanstack/react-query` for server state.
- **Network**: Umi Max request plugin (axios-based), configured in `src/requestErrorConfig.ts`.
- **Mock**: Express-style mock handlers in `mock/` and co-located `src/pages/**/_mock.ts`.
- **Backend API**: A separate Cloudflare Worker lives in `cloudflare-worker/` and is built with Hono. It is **not** an npm workspace and has its own `package.json`.
- **Deployment**: Static site deployed to GitHub Pages with CNAME `preview.pro.ant.design`.

## Key Configuration Files

| File | Purpose |
|------|---------|
| `package.json` | Project metadata, scripts, dependencies. Node `>=22`. Uses `npm` and `package-lock.json`. |
| `config/config.ts` | Umi Max `defineConfig`. Enables model, initialState, layout, locale, antd, request, reactQuery, access, analytics, tailwindcss, mock, openapi, utoopack, exportStatic. |
| `config/routes.ts` | Declarative route table. Route `name` maps to `menu.xxx` i18n keys; `access` gates visibility. |
| `config/defaultSettings.ts` | ProLayout defaults (theme, layout mode, colors). |
| `config/proxy.ts` | Dev proxy per `UMI_ENV` (`dev`, `test`, `pre`). |
| `config/oneapi.json` | OpenAPI schema used to generate `src/services/ant-design-pro/`. |
| `biome.json` | Linter and formatter config. Biome replaces ESLint + Prettier. |
| `vitest.config.ts` | Test runner config. Uses `happy-dom` and `@testing-library/react`. |
| `tsconfig.json` | TypeScript config with strict mode, path aliases `@/*`, `@@/*`, `@root/*`. |
| `doctor.config.json` | `react-doctor` / `antd doctor` ignore/overrides. |
| `.commitlintrc.js` | Conventional commits enforcement. |
| `.lintstagedrc` | Runs Biome check on staged files. |
| `tailwind.css` | Tailwind v4 entry with `@source "./src"`. |

## Build and Development Commands

```bash
# Install
npm install

# Development
npm start                 # dev server with mock data
npm run dev               # dev server without mock (MOCK=none)
npm run start:no-mock     # alias for dev without mock
npm run start:test        # UMI_ENV=test, no mock
npm run start:pre         # UMI_ENV=pre, no mock

# Build and preview
npm run build             # production build via max build
npm run preview           # preview dist on port 8000
npm run preview:build     # build then preview
npm run analyze           # build with bundle analyzer

# Code quality
npm run lint              # Biome lint + TypeScript check
npm run biome:lint        # Biome lint only
npm run biome             # Biome check --write (auto-fix)
npm run tsc               # type-check only

# Testing
npm test                  # vitest run
npm run test:coverage     # vitest run --coverage
npm run test:watch        # vitest watch
npm run test:ui           # vitest UI

# Code generation and utilities
npm run openapi           # regenerate src/services/ant-design-pro/ from config/oneapi.json
npm run simple            # IRREVERSIBLY strip project to simple version — commit first
npm run i18n-remove       # remove i18n infrastructure

# Ant Design CLI (dev dependency)
npx antd info <Component> # look up component props/API before writing antd code
npx antd demo <Component> <demo> # get working demo
npx antd lint ./src       # check for deprecated/problemac antd usage
npx antd doctor           # project health check
npx antd migrate <from> <to> # migration checklist
```

### CI vs Local Build

Local scripts call `max` directly (`max dev`, `max build`). CI installs the `utoo` toolchain via `utooland/setup-utoo` and runs `ut lint` / `ut build`. Both should produce the same output, but if CI-specific failures appear, verify with the `ut` commands after installing the toolchain.

## Code Organization and Conventions

### Page Co-location

Each page directory should contain:

- `index.tsx` — page component.
- `service.ts` — hand-written API helpers for non-generated endpoints.
- `_mock.ts` — co-located Express-style mock handlers.
- `data.d.ts` — local TypeScript types.
- `*.style.ts` / `*.less` — page-specific styles (prefer `antd-style` `createStyles`).
- `*.test.tsx` / `*.test.ts` — Vitest tests.

### Core Runtime Files

- `src/app.tsx`
  - `getInitialState()` fetches the current user via `GET /api/currentUser`. On 401 it redirects to `/user/login` with a `redirect` query.
  - `layout` returns ProLayout runtime config.
  - `request` sets `baseURL` to the Cloudflare Worker in production and merges `errorConfig`.
  - `rootContainer` wraps the app with `OfflineBanner` and `ErrorBoundary`.
- `src/access.ts` — returns `{ canAdmin: currentUser?.access === 'admin' }`. Used by route `access` fields.
- `src/requestErrorConfig.ts` — standardized error handling for `success`, `errorCode`, `errorMessage`, `showType`, plus network/offline handling.

### Routing

Routes are declared in `config/routes.ts`. The `name` field maps to `menu.<name>` keys in `src/locales/*/menu.ts`. The `access` field references keys returned by `src/access.ts`.

### Styling Priority

1. Tailwind CSS v4 for layout and utility classes.
2. `antd-style` v4 `createStyles` for theme-token-aware component styles.
3. CSS Modules.
4. Less only for legacy code; avoid in new work.

`src/global.tsx` imports `tailwind.css`. Global styles live in `src/global.less`.

### Internationalization

Eight locales are supported under `src/locales/`: `bn-BD`, `en-US`, `fa-IR`, `id-ID`, `ja-JP`, `pt-BR`, `zh-CN`, `zh-TW`.

Use `useIntl().formatMessage({ id, defaultMessage })` or `<FormattedMessage />`. Default locale is `zh-CN`.

### State

- Use `useModel('@@initialState')` for current user and layout settings.
- Use `useModel('filename')` for custom global hooks in `src/models/` (create the directory if needed).
- Use ProTable `request` for simple list data loading.
- Use `@tanstack/react-query` (`useQuery`, `useMutation`) for complex server state (e.g., `src/pages/table-list/index.tsx`).

## Testing Strategy

- **Runner**: Vitest (`vitest.config.ts`), not Jest.
- **Environment**: `happy-dom`.
- **Globals**: Vitest globals are enabled (`describe`, `it`, `expect`, `vi`).
- **Setup**: `tests/setupTests.ts` provides mocks for `localStorage`, `Worker`, `URL.createObjectURL`, `MessageChannel`, `matchMedia`, and `ResizeObserver`.
- **Test location**: `src/**/*.{test,spec}.{ts,tsx}`.
- **Excluded**: `src/pages/user/login/login.test.tsx` is excluded because it depends on Umi's Jest runner and cannot run under Vitest.
- **Coverage**: Provided by `@vitest/coverage-v8`. Coverage excludes `src/.umi/**`, `src/services/ant-design-pro/**`, `src/**/*.d.ts`, and `src/**/index.style.ts`.

Run tests before committing: `npm test`.

## Code Style Guidelines

- **Biome only** — do not add ESLint or Prettier configs.
- Biome ignores `src/.umi*`, `src/services`, `mock`, `dist`, `public`, `coverage`, `node_modules`.
- Formatter uses spaces and single quotes for JS/TS.
- JSX runtime is configured as `reactClassic` in Biome.
- Lint rules that are intentionally disabled: `noExplicitAny`, `noUnknownAtRules`, `useUniqueElementIds`, `useExhaustiveDependencies`, several a11y rules.
- Run `npm run biome` to auto-fix staged-level issues; run `npm run lint` before committing to verify.

## Critical Rules

1. **Never edit `src/services/ant-design-pro/` by hand.** It is generated from `config/oneapi.json` via `npm run openapi`.
2. **`src/.umi/` is auto-generated.** Delete it and restart the dev server if Umi behaves oddly.
3. **`npm run simple` is irreversible.** It deletes page directories, mocks, and dependencies. Commit or branch before running it.
4. **Always use Conventional Commits.** Husky + commitlint enforce this.
5. **Node ≥ 22 is required.** Use `npm` and keep `package-lock.json` in sync.
6. **Before writing antd code**, run `npx antd info <Component>` to verify props/APIs; do not rely on memory.
7. **Both lint gates must pass in CI**: `npm run biome:lint` and `npm run tsc`. The `antd-cli.yml` workflow also runs `npx antd doctor`, `npx antd lint ./src`, and `npx antd usage ./src`.

## Mock and API

- Local dev mocks come from `mock/` and `src/pages/**/_mock.ts`.
- Default mock credentials: `admin` / `ant.design` (admin access) or `user` / `ant.design` (user access).
- Production frontend points to `https://pro-api.ant-design-demo.workers.dev` via `baseURL` in `src/app.tsx`.
- The Cloudflare Worker in `cloudflare-worker/` exposes routes under `/api` and uses Hono + CORS.

## Deployment

- GitHub Actions build and deploy to GitHub Pages on pushes to `all-blocks`.
- `deploy.yml` sets `COMMIT_HASH` from `github.sha` so the frontend can display it.
- CNAME is `preview.pro.ant.design`.
- Cloudflare Worker is deployed separately from `cloudflare-worker/` with `wrangler deploy`.

## Security Considerations

- No bearer token is attached to requests by default; the interceptor in `src/requestErrorConfig.ts` has a commented-out example. Add authentication only intentionally.
- Production `baseURL` is a public demo worker; do not ship real secrets or PII to it.
- Mock credentials are public and only for local development.
- Cloudflare Worker CORS allows origins based on `corsOrigin()` and falls back to `https://preview.pro.ant.design`.
